# Checkpoint module (M7 foundation)

Purpose: save and restore the state of a flight in progress as a logical
object (DTO), with strict validation. No server, no JavaScript, no
WebAssembly: pure C and native tests only.

## Files

- `core/checkpoint.h` — DTO type, result codes, function prototypes.
- `core/checkpoint.c` — implementation.
- `core/test_checkpoint.c` — native tests (ASan/UBSan, -Werror).
- `web/Makefile` — `core/checkpoint.c` added to `CORE`; `core/test_checkpoint.c`
  added to `test-c`.

## DTO (core/checkpoint.h)

```c
#define CP_VERSION 1
typedef struct {
    int format_version;     /* must equal CP_VERSION */
    int ship_type;          /* enum ShipType */
    unsigned int route_seed;
    unsigned int generator_version; /* must equal FL_GENERATOR_VERSION */
    int mode;               /* only FL_MODE_AUTOPILOT or FL_MODE_MANUAL */
    float px, py, pz;
    float yaw, pitch;
    float throttle, speed;
    float fuel, hull, energy;
    unsigned int rocks_alive_lo; /* bit i = rock i alive, rocks 0..31 */
    unsigned int rocks_alive_hi; /* rocks 32..47 */
} Checkpoint;

enum CpResult { CP_OK = 1, CP_INVALID = -1, CP_UNAVAILABLE = -2 };
```

### Fields

| Field | Meaning |
|---|---|
| `format_version` | Format version; must equal `CP_VERSION` (currently 1). |
| `ship_type` | Ship type (`enum ShipType`); must be valid (`ship_spec != NULL`). |
| `route_seed` | Seed used to generate the route and rocks. |
| `generator_version` | Must equal `FL_GENERATOR_VERSION` (currently 1). |
| `mode` | Flight mode; only `FL_MODE_AUTOPILOT` (0) or `FL_MODE_MANUAL` (1). |
| `px, py, pz` | Ship position. |
| `yaw, pitch` | Ship heading. |
| `throttle` | Throttle lever (0..1). |
| `speed` | Current speed. |
| `fuel, hull, energy` | Fuel, hull integrity, energy. |
| `rocks_alive_lo` | Bit i = rock i alive (rocks 0..31). |
| `rocks_alive_hi` | Bit i-32 = rock i alive (rocks 32..47). |

## Functions

### `cp_validate(const Checkpoint *cp)` -> `CpResult`

Returns `CP_OK` or `CP_INVALID`. Fails (`CP_INVALID`) if any rule is broken:

- `format_version == CP_VERSION` and `generator_version == FL_GENERATOR_VERSION`
  (no migration in this version: different versions are invalid).
- `ship_type` is valid (`ship_spec` is not `NULL`).
- `mode` is `FL_MODE_AUTOPILOT` or `FL_MODE_MANUAL`.
- All floats are finite (no NaN, no infinity).
- `0 <= pz < route.length` (route length comes from `flight_init`, never
  hard-coded).
- `hypot(px, py) <= FL_CORRIDOR * 1.1`.
- `|yaw| <= FL_MAX_ANGLE` and `|pitch| <= FL_MAX_ANGLE`.
- `0 <= throttle <= 1`.
- `0 <= speed <= max_speed` of the ship.
- `0 <= fuel <= fuel_max`.
- `0 < hull <= hull_max`.
- `0 <= energy <= energy_max`.
- Rock-alive bits at or above `rock_total` of the route generated by the seed
  must be zero.

### `cp_capture(const Flight *f, Checkpoint *out)` -> `CpResult`

Captures an in-progress flight into a DTO. Returns `CP_UNAVAILABLE` if the
mode is `ARRIVED`, `DESTROYED` or `STRANDED`, or if any input is `NULL`; `out`
is left untouched on failure. Otherwise fills `out` and returns `CP_OK`.

### `cp_restore(const Checkpoint *cp, Flight *out)` -> `CpResult`

Validates the DTO first (`cp_validate`); `out` is left untouched on any
failure. On success: runs `flight_init(ship_type, route_seed)` on a temporary
`Flight`, applies the DTO fields and the live rocks, then copies to `out`.
Fields not part of the DTO (laser cooldown, flash, shake, held/pressed keys,
tick, lane phase, RNG state, event queue) start at zero.

## What is outside the snapshot and why

- `laser_cd`, `laser_flash`, `shake`: transient visual/cooldown state; restart
  at zero, acceptable because the checkpoint is for saving/resuming a flight,
  not for frame-exact replay.
- `held`, `pressed`, `tick`: input and frame counters; restart at zero.
- `lane_phase_x`, `lane_phase_y`, `rng`: used to generate the route and rocks
  at init; the route is regenerated from `route_seed` so they are not needed.
- Event queue (`ev`, `ev_head`, `ev_count`): semantic events already consumed;
  restart empty.
- `alert_prev`, `destroyed_rocks`: derived/auxiliary state; restart at zero.

The snapshot is intentionally small: ship state plus the rock-alive bitset.
Rock positions, sizes and shapes are deterministic from `route_seed`, so they
do not need to be stored.

## Evolving the format

Never change version 1. To add fields or change semantics:

1. Bump `CP_VERSION` to 2 (or higher) and add a new DTO layout.
2. Add a migration function that reads a version-1 `Checkpoint` and produces a
   version-2 one (validating the old data first).
3. Keep `cp_validate` for version 1 unchanged so old saves remain validatable.
4. Version 1 is frozen: old saves must never become invalid.

## What is still missing (M7)

- Link to the server (persistence API).
- JS / WebAssembly bridge (exposing capture/restore across the C/JS boundary).
- "Knowledge flags" and "Life-Safe" markers mentioned in the M7 design.

## Known gaps (Architect review)

- Rock hit points are not stored: a rock that was damaged but alive is restored with full hit points. Rock rotation angle is also not stored (visual only). Acceptable for M7 groundwork; revisit if damaged rocks must persist.
- Only a single route is covered. Route/world state, post flags, mind copy and debt arrive with later versions of the DTO (bump CP_VERSION and add a migration; never edit version 1).
- `yaw_rate` and `pitch_rate` (damped rotation, M2) are not part of the DTO: the format is unchanged and restore sets them to 0. They are re-derived from inputs after resume, so this does not affect correctness.
